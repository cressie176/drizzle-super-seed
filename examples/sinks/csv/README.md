# CSV files example

The same park domain as the other examples, generated as numbered RFC 4180 files a person can
review, diff, or hand to a spreadsheet or an ETL tool. There is deliberately no database here:
the artefact is the point. (Loading these files through a real `COPY ... FORMAT csv` is proved
by the library's own integration suite.)

```sh
npm run generate   # writes out/: one CSV per table, plus a manifest recording the seed
npm test           # reviews the files as files - counts, header, null vs empty, realism
```

What the files look like:

```csv
id,name,region,opened_at,latitude,amenities,active
1,Spokane Retreat,south-west,2025-04-07,58.3752,"[""shop"",""wifi""]",1
2,East Cary Retreat,wales,2022-04-04,53.5384,"[""playground""]",1
```

Worth knowing when reading or ingesting them:

- Files are numbered so lexical order is dependency order: parents sort before the tables that
  reference them.
- A null is a bare empty field; an empty string is a quoted one. That is exactly the distinction
  PostgreSQL's `FORMAT csv` makes, and it is visible in the raw text.
- Timestamps are RFC 3339 in UTC (a trailing `Z`), so the instant is in the text itself.
- `manifest.json` records the seed, so a reviewed dataset can be regenerated byte for byte.
